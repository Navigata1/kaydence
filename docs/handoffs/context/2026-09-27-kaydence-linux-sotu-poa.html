What the live test caught that the bench didn't

The first speed fix, a 384-frame window floor, passed the bench but typed "As not" in the live run. Kaydence's voice detector sends each pause-separated fragment to whisper on its own, and a lone 1.47 s "ask not" garbles in a narrow window. Raising the floor fixed the word, but each pause then cost ~0.6 s, which failed the budget. The shipped design sends the whole dictation as one pass. It is about 2.5× faster than per-fragment passes, and gave the same correct text in 3 of 3 rounds. Per-fragment passes read "And so am I fellow Americans" once.

Findings

tonight's first · earlier ones below
F7 · fixed tonight

Speech recognition was 4–6× slower than it needed to be

There were two causes: a fixed 30 s encoder window on every pass, and a separate pass for every pause. #58 fixes both, with one pass per dictation (up to 25 s) and a window fitted to it: clamp(⌈s·50⌉+128, 640, 1500).

F14 · new, fixed

Fragments garble in narrow windows

A lone 1.47 s "ask not" read "S not." at 384 frames and "as not." at 448–512, and was correct from 576 up. The floor is 640, and joining the fragments into one pass makes lone short passes rare.

F12 · fixed tonight

A field focused before tracking read as "Unknown"

When no accessibility event vouches for the focused app, Kaydence now asks directly: it walks at most 3,000 nodes within 150 ms on a helper thread. A timeout still means Unknown. The exact case that once typed into the field is now refused.

F15 · new, fixed

Flushing isn't delivering

The first focus guard only flushed each batch, so 12 queued keys followed focus to the new window. Each batch is now round-tripped through the compositor before the focus check. The new window received 0.

F16 · model edge

"Americans asked not"

On the 11 s clip, base.en reads the whole sentence this way, and it does the same with the full 30 s window. The old per-fragment path said "Ask not!" only because it heard those two words alone. The fix is a larger opt-in model (K-25), not a wider window.

F13 · narrowed

GTK4 drops in-flight keys on focus-out

Mid-delivery, this is now covered by the focus guard. A client that loses focus within milliseconds after the last key could still drop keys; that was seen only when a test harness moved focus. An optional ≤ 100 ms settle is noted.

F1 · F2 · proven

Keybind leak and keymap switch

Only 48 plain-printable keycodes are used, and each keymap gets a fresh virtual keyboard. Live typing is 8/8, including the 7-keymap passage, with zero side effects.
