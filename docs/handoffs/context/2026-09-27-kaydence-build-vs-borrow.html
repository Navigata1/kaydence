Build vs Borrow

Are we reinventing wheels that proven open-source projects already built? This study covers voxtype, which Omarchy installs on this machine; the "OSS" repo you heard about; the seven tools in the Weesper Neon Flow article; the closest cross-platform peers (Handy, OpenWhispr, Epicenter); and Omarchy's own tools. It scores all of them against Kaydence's original pro/con list.

Spoken aloud, "OSTT" sounds like "OSS-T". Its author's launch video calls this speech-to-text tool a "Text-to-Speech app", which would explain the STT/TTS confusion. It shares Kaydence's core stack but outputs to the clipboard rather than typing into apps. Its "re-run a recording with another model" feature is worth copying, and Kaydence's saved audio makes that nearly free. To check: open ostt.ai. If it's not OSTT, try Open Speech Studio next.

voxtype, installed here

MIT · Rust · 1,560★ · Omarchy's default

Pros

  • Many engines: whisper-rs, parakeet-rs, Moonshine, SenseVoice and more
  • GPU variants: Vulkan, CUDA, ROCm, NPU
  • Streaming and meeting mode
  • Official Omarchy integration: installer, bar widget, menu
  • Good cleanup rules, including a filler list with per-language collisions

Cons

  • Shells out to wtype and ydotool, and inherits their bugs: dropped first characters (#61), CJK corruption (#695), German y/z (#120), stuck modifiers (#538)
  • No password or focus safety
  • Audio lives in memory, so a crash loses the dictation
  • No Windows, and effectively one maintainer

Take (MIT)

  • Window rounded up to a multiple of 8, and a retry at the full window on degenerate output
  • Silence and dead-stream detection; drop known hallucinations
  • Its issue list becomes our regression tests
  • Held-modifier guard via a Hyprland submap (K-11)
  • A status --follow bar feed and a cancel verb

Keep ours

  • Socket CLI. Handy found WebKitGTK uses SIGUSR1 internally, so avoid signals.
  • Audio written to disk before ASR
  • In-process Unicode typing
  • Password and focus safety

For you: voxtype has been running on this machine since 18 Sep. It logs every dictation in full to journalctl --user -u voxtype and keeps about 390 MB resident. Its F9 and SUPER+CTRL+X bindings don't clash with Kaydence's F10 and SUPER+ALT+D. Turning it off is your call: systemctl --user disable --now voxtype.

Correction to one agent claim: Kaydence's virtual keyboard does not have wtype's Chromium bug, where the 14th character lands on keycode 22 and acts as BackSpace. Kaydence only uses 48 printable-position keycodes and never Esc, BackSpace, Tab or Return (xkb.rs, the F1 fix). The remaining gap is a live typing test in Chromium or Electron, which is now on the list.

What this changes

ADR-0023 · PR #57

Strengthened. It matches the field's consensus design, and Kaydence alone has in-process Unicode typing with password and focus safety.

ADR-0024 · PR #58

The technique is used in the field, but voxtype #124 makes GPU and large-v3-turbo loop checks mandatory before acceptance; the handoff covers them. Adding the 8-alignment and degenerate retry first is about an hour of cheap insurance.

ADR-0016 · Parakeet / VAD

Worth revisiting. transcribe-cpp plus earshot could replace the planned ONNX Runtime dependency, which also avoids its AVX2 crash on older CPUs.

Mac & Windows verification

the handoff that feeds both ADR decisions

These are work packets for the Mac (Apple Silicon) and Windows (ARM64, plus x64 if available). For PR #58: an engine A/B, a reference-bench A/B, a live smoke test and a large-v3-turbo loop check. For PR #57: installer contents, live hotkey dictation and password-field refusal. Clips are cut deterministically, pass criteria come with a Linux reference row, and results come back as evidence files and a hand-back manifest on the PRs.
