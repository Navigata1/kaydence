Why CI isn't enough

ADR-0024 · #58

Accuracy on your hardware

CI never runs the golden transcription test, and Metal and ARM or x64 SIMD can behave differently from Linux x86.

ADR-0023 · #57

Mac/Windows still dictate

It changes the shared hotkey-edge code and which binaries go into every installer. CI builds it but never dictates with it.

Field warning: voxtype shipped the same speed-up as ADR-0024 in January. Users on large-v3-turbo + GPU got repeated-phrase loops on 3–8 s phrases, so voxtype switched it off by default (voxtype #124, #130). PR #58 already has the fixes voxtype landed on, but only your GPU lanes can confirm it's safe.

PR #58 · ADR-0024

one pass per dictation, fitted window
T1

Engine A/B

required

Run each clip on kd-main and on kd-pr58, per lane. On Mac: Metal (--features asr-whisper-metal, and the output must say lane=LocalGpu) and CPU (KAYDENCE_WHISPER_LANE=cpu). On Windows: CPU only.

KAYDENCE_WHISPER_MODEL=$MODEL KAYDENCE_WHISPER_CLIP=$CLIP KAYDENCE_WHISPER_LANE=cpu GGML_NATIVE=OFF \
  cargo test --release --features asr-whisper --test asr_golden -- --nocapture 2>&1 | grep -E "final_text|metrics"

main failing its 1,200 ms assertion on slow lanes is expected; record the text anyway. On c1 the model says "asked not" on both sides, which is a known base.en edge case.

T2

Reference bench A/B

required

This exercises the full pipeline, including voice detection and the join. Build reference-bench in each worktree, then run node scripts/bench-reference.mjs on clip c2 with the model id and sha256 variables (the exact command is in the source file). Record p50, p95, idle RAM and status. On Linux: p95 4,062 → 742 ms. Pass: pr58 p95 ≤ 1,200 and no worse than main. Mac Metal RAM already failed its budget in July, so record the change without gating on it.

T3

Live smoke

required

Run the app from kd-pr58 as usual, with base.en q5_1. Dictate "Yes.", then a sentence with a deliberate 1-second pause, then about 15 s of speech. Pass: the text is right, comes out as one sentence, and lands in about 1 s.

T4

large-v3-turbo loop check

recommended · Mac Metal

This is the combination behind voxtype's loop reports. Download ggml-large-v3-turbo-q5_0.bin and record its sha256; the registry still says TODO. Repeat T1 on Metal for c2, c3, c4 and the say clips. Any repetition is a FAIL.

PR #57 · ADR-0023

Linux lane, shared code on Mac/Windows
T5

Installer contents

required
pnpm install && pnpm --filter kaydence-desktop build
cd apps/desktop && cargo tauri build --features asr-whisper-metal    # Windows: --features asr-whisper

Expected: only kaydence and kaydence-ctl. There should be no selftests and no reference-bench; main ships one stray selftest, which is the bug #57 fixes. kaydence-ctl record status must print "the record control command is only available on Linux", exit non-zero, and not crash.

T6

Live hotkey dictation

required

Hold-to-talk twice into TextEdit or Notepad. A tap shorter than 250 ms must be discarded. Try toggle mode once if it's configured. Pass: it behaves the same as on main.

T7

Password-field refusal

required

Repeat the July refusal check: UIA IsPassword on Windows and AXSecureTextField on macOS. The field must receive nothing, and the app must show a hold.

Hand back, then decide

  • For #58, push ops/mission/evidence/2026-09-27-adr0024-<macos-arm64|windows-arm64|windows-x64>.txt to the PR branch.
  • For #57, push …-adr0023-<platform>-smoke.txt. If a push is refused, use gh pr comment with the file instead.
  • Post a handoff manifest (AGENT_INTEROP_PROTOCOL §3) as a PR comment. Its claim_status is verified, falsified or blocked; never report "blocked" as "passed".
  • "Go on 0023" if T5–T7 pass on both machines. Then commit the acceptance, mark the PR ready, and merge with merge commits in the order #56 → #57 → #58, rebasing in between.
  • "Go on 0024" if T1–T3 pass on every lane and T4 shows no loops.
  • If a lane regresses: don't merge. Harden first (voxtype's 8-alignment and a full-window retry on degenerate output), raise that lane's floor, or limit the fitted window to CPU lanes. Then re-run that lane.
