## T7: password-field refusal (verified)

Method (July's 2026-07-09-windows-injection.txt, repeated on #57's build):
- #57's `uia-selftest` (release, dev-tools default) drives the production
  `inject_committed_text` policy path into focused local WinForms TextBoxes.
- Ground truth is what the TextBox received: its TextChanged event writes to a
  temp file.
- A clipboard sentinel detects clipboard leakage; the operator's clipboard was
  saved and restored.
- `uia-selftest.rs` is byte-identical on main and #57. #57's `inject/mod.rs`
  changes are `cfg(linux)` plus two pure modules (hyprland, xkb) that compile
  on Windows.

| Case                                   | UIA field | Outcome                                            | Field received | Clipboard after |
| editable / --inject (positive control) | Editable  | Injected { method: Native }                        | "T7 editable OK" | sentinel (unchanged) |
| password / --inject (policy path)      | Secure    | Held { reason: SecureField }                       | nothing        | sentinel (unchanged) |
| password / --synth (SendInput rung)    | Secure    | refused: "secure field focused (non-negotiable #8)"| nothing        | sentinel (unchanged) |
| password / --paste (clipboard rung)    | Secure    | refused: "secure field focused (non-negotiable #8)"| nothing        | sentinel (unchanged) |

Not covered: the full-app hotkey → ASR → Held path. It needs live speech, and
the operator scheduled live runs in Part C.
