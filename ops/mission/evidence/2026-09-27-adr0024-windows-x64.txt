## FINDING: Windows x64 whisper.cpp is compiled without optimization

The default x64 build (cargo → whisper-rs-sys 0.15.0 → cmake crate 0.1.58 →
Visual Studio 17 2022 generator) passes NO /O switch to cl.exe for the Release
configuration of ggml-cpu, ggml-base and whisper.
- Ground truth: the MSBuild CL.command tlogs for those three libraries list
  only /MD and /arch:AVX2, with no /O2 or /Ox. cl.exe's documented default is
  /Od (optimizations off).
- The cmake crate sets CMAKE_C_FLAGS_RELEASE / CMAKE_CXX_FLAGS_RELEASE to
  "-nologo -MD -Brepro -W0", which replaces CMake's "/O2 /Ob2 /DNDEBUG".
- SIMD is enabled: AVX, AVX2, FMA, F16C, BMI2, SSE4.2.
- Setting CFLAGS/CXXFLAGS=-O2 does NOT reach those command lines.
- Setting the cl.exe environment variable CL=-O2 does, and is the only change
  between the two rows below.

Same source (main f5f4eb6), clip c2:
  as-built (no /O)  transcribe_ms 15,943   "Ask not what your country can do for you."
  CL=-O2            transcribe_ms  1,941   (identical text)   -> 8.2x

Scope:
- Likely affects the Windows x64 release build in CI (same cargo/cmake/VS path;
  NOT verified on the runner).
- The Windows ARM64 lane uses Ninja + clang-cl (scripts/windows-arm64-build.ps1)
  and was not examined here.
- Recommended follow-up (not implemented; outside this packet): make the
  Windows ASR build pass /O2 explicitly, then add a CI assertion that fails if
  the Release tlog lacks /O2.
